MathProblemBank 新背景图导入、高清重绘与主题配色统一提示词

使用方法：
1. 把准备导入的原始图片作为附件发给 Codex。
2. 将下方“可直接发送给 Codex 的提示词”完整发送给 Codex。
3. 如果一次导入多张图片，必须对每一张图片独立执行全部检查，不得用同一个主色套用多张图片。

================ 可直接发送给 Codex 的提示词 ================

请在当前 MathProblemBank 项目仓库根目录中完成我本次附加背景图的高清重绘、导入、主题配色和验证。不要只给出建议；请直接检查图片、生成最终文件、修改项目并运行验证。必须保留现有背景轮播、界面和 PDF 主题功能。

一、固定输出规格

1. 本机物理显示分辨率为 2560 × 1600，宽高比为 16:10。每一张最终背景图必须恰好为 2560 × 1600 像素；推荐保存为无损 PNG。不得只修改 DPI 元数据，不得输出近似尺寸。
2. 必须先查看原图，确认主体、构图、焦点、画风、文字、光线、色彩关系和需要保留的细节，然后使用图像编辑/生成模型进行真正的高清重绘。普通双线性、双三次或 Lanczos 放大只能用于最后的小幅精确尺寸归一化，不能冒充高清重绘。
3. 重绘必须忠实保留原图的核心内容：人物或物体身份、脸部特征、姿态、服装、关键道具、文字内容、画风、光照方向、主色关系和整体氛围均不得擅自改变。不要新增人物、肢体、文字、水印、边框或无关装饰，不要把原图改成另一种画风。
4. 如果原图不是 16:10，优先使用内容感知扩图/重绘自然延展画布，使重要主体完整保留；不要为了凑比例裁掉头部、脸、手、关键物体或文字。不得留黑边、白边、模糊填充边或镜像复制边。只有原图边缘确实存在可安全裁去的冗余区域时，才允许少量裁切。
5. 最终图必须适合作为全屏桌面应用背景：细节清晰但不过度锐化；线条、头发、轮廓、渐变、天空、墙面和大色块干净；不得出现压缩块、重影、涂抹脸、畸形手、重复纹理、断裂线条、乱码文字或明显生成痕迹。
6. 输出后必须读取文件本身验证：尺寸严格等于 2560 × 1600、文件能正常解码、没有透明空洞，并在全图视图下进行一次视觉检查。不得只相信生成工具返回的尺寸说明。

二、主色选择的严格规则

主色必须从“最终重绘后的图片”中选择，而不是从原始低清图、文件名、题材印象或人物身份推测。主色的含义是：图片中真实存在、面积足够大、能够代表整张图片视觉基底、用于界面和 PDF 后仍自然协调的非黑色颜色。

1. 面积优先，不以醒目程度优先。优先考察天空、墙面、地面、海面、树叶、大面积背景、大片服装或连续图案等占画面较大比例的区域。小面积高饱和装饰、夕阳、灯光、眼睛、肤色、发饰、围巾、文字、边线和局部高光即使非常醒目，也不能压过面积明显更大的色块成为主色。
2. 禁止把整张图中所有“有颜色的像素”直接求平均。该方法会让灰黑图片被少量棕黄装饰错误染成棕黄色，也会让蓝色夜景被少量粉色灯光带偏。
3. 不得丢弃低饱和像素。灰色、灰蓝色和中性色可以是正确主色；灰度图片必须选择画面中大面积出现的中灰或灰黑色，不得为了“更鲜艳”而凭空制造蓝色、棕色、黄色或紫色。
4. 主色不能是黑色或视觉上等同于黑色的颜色。机器初筛时忽略近黑像素（可采用 HSV Value < 48）；如果黑色占比最大，应从剩余颜色中选择面积最大的非黑色区域。最终主色至少应满足 max(R,G,B) >= 75，通常优先选择 HSV Value >= 92 的真实大面积色块，而不是把黑色人工调亮后冒充图片原色。
5. 近白背景和白色高光通常不适合作为界面主题色，机器初筛时可忽略 HSV Value > 242 的像素，再从其余真实色块中选择；但不能因此跳到一个面积很小的艳色。若画面主要由白色与某种浅灰/浅蓝构成，应选择大面积的浅灰、灰蓝或其他可见非白色基底。
6. 推荐的机器候选方法：把最终图缩小到约 96 × 96；忽略 alpha < 32、近黑和近白像素；不要按饱和度过滤；将 RGB 每通道按约 32 的步长量化分桶；按像素数量找到面积最大的颜色簇，并计算该簇平均色。这个结果只是候选，必须再与原图并排人工核对。
7. 渐变、纹理或同一大区域可能被量化拆成相邻颜色簇。人工复核时应把视觉上属于同一大区域的相近颜色合并理解，选择其中最能代表该区域的中间色。不要机械地因单个桶略大就选择肉眼明显不占大面积的颜色。
8. 必须制作或临时生成“完整图片 + 主色色块 + HEX 值”的对照视图进行审核。判断标准只有两个核心条件：该颜色不是黑色；该颜色在图片中大面积真实出现。若色块与图片第一眼明显不协调，必须重新选择。
9. 主色使用大写 `#RRGGBB`。同时为 `BACKGROUND_PALETTES` 给出三个颜色：
   - main：按以上规则选出的真实大面积主色；
   - dark：与 main 同色相、约深 10%–12% 的稳定深色版本，但不得压成黑色；
   - auxiliary：优先选择图片中另一个面积较大或明确协调的真实颜色。若图片近乎单色，使用克制的同系或中性变体，不得随机生成互补色。

三、导入项目和自动化要求

1. 将最终图片保存到：
   shared\ui\assets\carousel
   文件名必须唯一、稳定且不覆盖现有图片；只保留最终版本，不把中间草图、对照图或临时文件留在轮播目录。
2. 在 `shared/scripts/problem_bank_center_qt.py` 的 `BACKGROUND_PALETTES` 中为每张新图加入人工审核后的 `(main, dark, auxiliary)`，不要只依赖自动缓存。若普通界面裁切使主体偏离，可按实际构图在 `BACKGROUND_FOCAL_POINTS` 中增加焦点位置。
3. 清理该新图可能产生的旧自动配色缓存，确保界面读取人工审核结果。不得删除或改变其他背景图的已审核配色。
4. 在普通界面背景模式和纯背景查看模式下分别检查：图片能被发现、轮播顺序正常、没有拉伸、黑边、白边或低清放大，主体位置合理，界面主色确实随该图片切换。
5. PDF 主题必须与 PDF 实际显示的本地封面一致。如果本次新图被分配给现有项目封面，必须同步 `cover_background`、本地 `cover_file` 和 `theme`，重新生成对应 PDF，并渲染封面及至少一页正文检查侧边色、标题装饰色和正文标题框。不得只修改全局配色表而留下旧的项目主题元数据。
6. 更新回归保护：验证所有当前背景都有人工配色、主色不是有效黑色、新图片尺寸为 2560 × 1600；同时覆盖灰度大面积 + 小暖色点缀、黑色大面积 + 次大非黑色区域等自动取色场景。
7. 运行 `python shared/scripts/regression_core.py` 和 `git diff --check`。删除所有临时对照图和构建审计文件；不要修改无关用户文件，不要自行提交 Git，除非我明确要求。

四、最终汇报

完成后逐张报告：最终文件名、尺寸、main/dark/auxiliary HEX、选择 main 的大面积图像区域、是否加入焦点设置、是否影响现有 PDF，以及验证结果。任何无法确认的构图或颜色必须明确说明，不能猜测。
