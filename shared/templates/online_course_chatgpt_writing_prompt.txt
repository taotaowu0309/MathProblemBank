POST-DRAFT TEXTBOOK SELF-CHECK

Before the import check, ChatGPT Work compares each finished subsection with the
actual passages read in the primary textbook, reference books, and author notes.
Look for in-scope explanations, missing steps, examples, counterexamples, results,
and figures that make the argument easier for a beginner to follow. Check what each
example computes and where each hypothesis is used. Add useful material to the
body, reconcile its notation and assumptions, and update the affected items and
reading notes in SOURCES.json. Record concrete reasons for deferring nearby topics.
The writer completes this step using the existing source record.

Compare the full hypotheses and generality of each relevant source result with
the body. When the body gives only a two-factor, finite-dimensional or numerical
case, assess whether the general statement should also be included. Look for
equivalent formulations, nearby consequences and explicit constructions that
connect the concepts already taught. Record the named result, its actual use in
the body, or a concrete reason and destination for deferring it in reading.note.
Overlapping definitions alone do not establish that an entire source section
overlaps the finished notes.

Match prerequisite reminders to the reader's recorded background. Trace every
substantive proof step to its justification and hypotheses. Cite the specific
earlier result when it has already been proved. For a nontrivial result used
without a previous proof, state exactly the version needed with its hypotheses,
identify the objects to which it applies, and check the conditions. Prove local
lemmas and intermediate computations needed for the current topic. When a
substantial theorem belongs outside the topic, explicitly identify it as an
assumption and give a verified source and proof location. Check existence,
uniqueness, well-definedness, choices of representatives, map properties,
quantifiers, both directions of equivalences, and possible circular dependencies.
Distinguish proofs owed in the current episode from prerequisites whose proofs
belong to later textbook chapters or sections. Record each deferred result, its
destination and the scope reason in reading.note. If the source only states a
result, say so; never label that statement location as a proof location.

Before drafting, privately create a CONTINUITY COLLISION LEDGER. For every

appear, identify its principal ownership location and classify the proposed use as:

- already established;
- minimal restatement needed;
- new strengthening;
- new proof revisited;
- preview becomes formal theory.

Every substantial mathematical object should have one principal ownership

preview that the locked target now develops as formal theory. Never repeat a result
merely because the current evidence or mapped source mentions it again.

WHOLE-UNIT EXPOSITION

READABILITY STANDARD (USER POLICY, 2026-11-07)

Use the user's step-by-step explanation of operators and polynomial modules as
the required level of exposition. Begin with a familiar object or an actual
calculation, explain the question a new concept answers, and connect it to what
the reader has already seen. Distinguish elements, scalars, functions, spaces of
functions, scalar rings and actions; give the domains and codomains of maps.
Spell out the bridges between concepts, including constructions in both
directions and why they recover the original data. Write the key intermediate
equalities, their justifications, and where each hypothesis is used. Induction
includes its base case and step; equivalences include both directions; constructed
maps receive the relevant well-definedness, linearity, injectivity, surjectivity,
inverse and uniqueness checks. Cite a specific earlier result when reusing it
and explain its application to the current objects.

Compute concrete examples and carry a useful example through related concepts.
A formula or an example's name alone does not supply its explanation. The
reader's prior algebra or analysis background is not permission to omit these
connections. Check definitions, remarks, examples and transition paragraphs as
carefully as named proofs. A reader's ability to reconstruct a missing argument
is not the readability criterion. When revising existing notes, retain every
existing in-scope conclusion, hypothesis, argument, example, reference contribution
and original figure, and improve the whole requested range, not only the few
locations the user has already identified. Keep the established scope rules;
expository detail does not authorize developing later chapters early.

Use the supported semantic environments truthfully. Definitions, results,

PROOF OWNERSHIP

Apply the five-category decision rule in `UNEXPANDED_PROOFS_PROMPT.txt` to every
nontrivial result before deciding whether to prove it. Complete proofs are required
for current target results and explicit current obligations. Previously established
results are cited or minimally restated, not proved again. External prerequisites
are stated in the exact version needed but are not proved unless current recording
evidence, explicit mapped-reference coverage, or an evidence obligation assigns
that proof to this target. Contextual claims remain prose. The mere use of a
`theorem`, `lemma`, `proposition`, or `corollary` environment does not override
this ownership decision.

Every retained example must still contain the calculation or verification needed
to establish what that example claims. Definitions must state complete hypotheses,
object types, operations, and conditions. Do not manufacture a proof obligation
for a definition, a motivational observation, or an already completed earlier
result.

CORE NARRATIVE AND OPTIONAL SUPPLEMENTS

Mathematical completeness does not require every long technical proof to interrupt
the first-reading path. State the core definition or theorem before a long
target-owned technical supplement whenever mathematically legitimate. Mark the
supplement clearly with a short first-reading remark, place supporting lemmas with
it, and resume the main conceptual thread immediately afterward. Advanced material
is retained when it is owned by the current target, but it must not obscure the
unit's core narrative.

When the unit invokes an external theorem, state the exact version and hypotheses
needed before using it. Do not silently invoke an unspecified theorem, and do not
expand the external theorem into a new chapter-length proof unless its proof is
assigned to the current target.

EXERCISE AND SOLUTION CONTRACT

A recorded lecture subsection contains no exercises or exercise solutions: the user
requests them separately. This contract applies to textbook exercise companion units.

Every exercise statement owned by the target must have exactly one complete solution
immediately after it. Never write "left to the reader", "the proof is similar",
"obvious", "routine", a hint instead of a solution, an answer-only line, or a
placeholder.

For a standalone exercise use:

\begin{exercise}
<complete exercise statement>
\end{exercise}

\begin{solution}
<complete detailed solution>
\end{solution}

For a numbered exercise set inside a top-level `enumerate`, keep each statement
and solution in the same `\item`; put `\textbf{Solution.}` alone on its own source
line and begin the answer in the following paragraph. A detailed solution must
justify every nontrivial implication and treat all relevant cases and boundary
conditions.
