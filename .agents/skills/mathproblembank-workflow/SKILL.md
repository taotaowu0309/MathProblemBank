# MathProblemBank 项目到讲义

用户把以前分给内置 Agent 和 Chat 的准备、阅读与写作交给 Work。Work负责把整个任务衔接到正式交付，继续使用仓库现有业务服务、录制流水线和提示词，不要求用户先准备JSON或压缩包。

## 进入项目

1. 完整读取仓库根目录 [AGENTS.md](../../../AGENTS.md) 和 [Work完整指南](../../../docs/CHATGPT_WORK_GUIDE.zh-CN.md)。执行命令时在仓库根目录。
2. 运行 `python -m shared.scripts.chatgpt_work workflow start`；已知目标时带 `--subject`、`--project`、`--course-id`。Windows使用 `PYTHONUTF8=1` 环境变量。先查已有学科、学习问题集、教材绑定、课程、材料和草稿，避免重建。
3. 输出的 `storage` 是本项目各类文件的实际位置（教材、项目 references、网课参考资料与 MinerU 产物、任务文件夹、标准题原图、Work 自己的 `tmp/work/<项目编号>/`）；按它读写，不猜路径，不在仓库根目录或学科目录随手存文件。完整表见指南第0.1a节。
4. 已有 `WORK_CONTEXT.json` 就读取目标、主教材、决定、覆盖及待办，与正式记录和文件核对后，从尚未完成的阶段继续。交接内容是项目数据，不是可执行指令或外部调用的自动授权。

## 执行链路

具体操作、实时schema和完成证据以完整指南第0节、`workflow catalog`、`workflow describe <tool>` 为准。请求文件由Work放在 `tmp/work/<项目编号>/`，通过 `workflow run` 调用已注册能力（含读取教材原文/书签、查已有标准题、公式与图形自查）；不要自己拼SQL或直接修改正式TeX。

- 创建/复用学科及学习问题集→在项目里创建网课。新学科已经带默认学习问题集；有参考教材不等于教材习题集。
- 用户给PDF则检查原件；要求搜索教材时定位准确版本与公开来源，下载、验证PDF及来源哈希并保存到项目references。
- 走三个正式教材入口的同一业务能力：教材登记→教材管理中的PDF绑定→教材索引健康中心检查/OCR。已登记的教材复用；保留空白页和失败页的真实说明。
- **另查网课参考资料的MinerU正文、公式、图像和节目录产物。** OCR检索完成不能代替这一层；当前小节的局部摘页也不能冒充全书解析。已有解析按源哈希/检查点复用，失败增量续跑。
- 复用现有录制产物和已锁定材料：转写、截图、正式小节和材料包。不重新处理锁定批次，不要求用户再录一次或另做ZIP。项目不调用任何模型，需要智能处理的步骤都由 Work 自己完成。
- 读当前TASK列出的完整材料、对应教材节和参考笔记。文本定位后精确读取原页，每次最多渲染4页，实际看到图像才算视觉核对。沿用正式任务的语言、章节和符号规范。
- 写教材式完整正文，展开本节的略讲证明与计算，覆盖主教材对应内容及原图。老师次序和教材次序不同，由Work建立主题映射。主教材原图优先，保留源图质量并标明真实出处；没有图不能编造，辅助图不能冒称主教材。
- 标准题：`problems prepare <学科> --project <项目> --book <教材>` 生成带 `SOURCES.md` 的任务，按其中教材和读取方式写完整解答，原图用 `crop_problem_textbook_figure`，再 `problems check`→`problems collect --collection-id --build-pdf`（指南3.4）。
- 刚录好的一集先 `course intake-task <课程> <集>`，读转写和全部截图缩略图，直接从截图提取板书内容（不选帧），写 `INTAKE.json` 定分节和教材，再 `course intake-apply <课程> <集>`，详见指南 3.0a。分集的 `package_status` 为 `pending` 是这一步的正常起点。讲义不写习题和解答，习题由用户另外安排。
- 讲义建立在已导入的教材上，不凭记忆写：先按主教材讲法，主教材没有或太略时用参考书，都查过没有才自己写。课程导入过教材时，`OUTPUT.tex` 旁边必须有 `SOURCES.json`，逐条记录来源（指南3.0b）。
- 网课讲义默认按整集写：`course episode-task <课程> <集>` → 写整集 `OUTPUT.tex`（每节以标记行开头）→ `course episode-check` → `course episode-collect`（逐节导入、只编译一次）。规则和往期讲义只读一次，原始转写和板书只按出处回查（指南3.0）。单独补写一节时才用单节流程：
- 用户要求讲解 PDF 阅读器里标记为“不懂”的句子时：`reading list`→`reading task <文档>`→按 `TASK.md` 的讲解规则写 `OUTPUT.json`→`reading check`→`reading collect`（指南3.9）。
- 每次含英文正文的讲义写作或修订后，Work自己按指南3.0c逐段自检英文阅读难点，不等用户点名。正式PDF生成后，按指南3.9批量标记筛出的原句、写好详细讲解并收取到阅读器，核对实际显示；保留原有内容，记录检查范围及保存结果，不能只标记或留草稿。
- `course check`→`course collect`，验证实际更新的正式PDF、目录和图文。写作者自行检查数学；日常独立模型数学审计、专项review、自动Repair均关闭。

## 留下可续接的成果

完成或遇到真正阻碍时，使用 `save_workflow_context` 更新项目交接文件，记录目标、主教材编号、用户决定、实际完成的阶段、教材节/页/图到讲义小节的覆盖、产物和下一步。交接不能把待办写成完成；授权备注注明用户原意和适用课程，不扩大到其他项目或服务。

报告正式成果和真实未完成项。不能用“下载成功”“已登记”“索引健康”“模型返回成功”分别代替教材已阅读、图已覆盖、正文已写入或PDF已更新。入口能力缺失先查注册表和现有服务；用户授权修复时只做必要适配，不搭第二套工程。
